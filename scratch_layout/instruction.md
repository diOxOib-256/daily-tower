# 実装指示：スクロールなしで遊べる画面レイアウト（2026-11-19）

対象リポジトリ：`ysgekzk-boop/daily-tower`（作業コピーはあなたの環境のものを使ってください）
前提 head：`98e824c`（敵HPカードの最大幅修正まで含む最新）

## 目的

ゲームプレイ画面（戦闘画面）がビューポートより縦に長く、ページスクロールしないとコマンドや装備欄に届かない。**ページ全体を 100dvh に収め、はみ出す内容はパネル内部のスクロールにする**。

現状の実測（フロア1の戦闘画面、ページのはみ出し量）：
- 1920×1080：+237px
- 1440×900：+324px
- 1366×768：+388px
- 390×844（モバイル）：+304px

## 現在の構造（目安）

- `src/App.tsx` ルート（733行付近）：`min-h-dvh flex flex-col`
- ヘッダー（736行付近）
- `main`（806行付近）：`mx-auto flex w-full max-w-[1760px] flex-1 flex-col gap-3`
- 戦闘ビュー：`BattleStage2D`（ステージ高さはコンポーネント内の固定クランプ：通常 `lg:h-[clamp(26rem,52dvh,36rem)]`、ボス `lg:h-[clamp(30rem,58dvh,40rem)]`）→ コマンド節 → メッセージログ＋現在の装備の行
- モバイルではコマンド／メッセージ／装備のタブUIがある（既存の仕組みを維持すること）
- イベント／報酬／次元跳躍などの画面は `max-w-4xl flex-1 flex-col justify-between` 系の構成

## 要件

1. **戦闘画面はページスクロールなし**：上記4ビューポートすべてで `document.documentElement.scrollHeight <= window.innerHeight` を満たす。ステージ、コマンドカード、メッセージログ、装備パネルがすべてビューポート内に収まり、メッセージログと装備リストは内容がはみ出す場合にパネル内部でスクロールする（`overflow-y-auto`）。
2. **レイアウト方針**（細部は任せるが、この方向で）：
   - ルートを `h-dvh overflow-hidden flex flex-col` にし、ヘッダーは `shrink-0`、`main` は `flex-1 min-h-0` の flex カラムにする。
   - 戦闘ビューは `h-full flex flex-col min-h-0` とし、ステージラッパーを `flex-1 min-h-0` にして残り高さを吸収させる。`BattleStage2D` の固定クランプ高さはやめ、親の高さに追随（`h-full`）させる。ただしステージが潰れすぎないよう最小高さ（目安 200px 前後）を確保し、スプライトとHUDが判読できること。ボス戦でステージをやや大きく取りたい場合は flex の比率で調整してよい（固定pxにしない）。
   - コマンド節は `shrink-0`。下段（メッセージ＋装備）の行は高さに上限のある配分（例：`flex-none` で 26〜32dvh 程度、短い画面では縮む）にし、両パネルとも内部スクロール可能にする。
   - 新システム解放告知バナーとストレージエラーのバナーは `shrink-0` の行としてステージ上に置く（表示中はステージが少し縮むのは可）。
3. **戦闘以外の画面**（タイトル、イベント、報酬、次元跳躍、フロンティア、各種モーダル）：動作を変えない。内容がビューポートを超える場合は `main` の内部スクロール（`overflow-y-auto`）で賄い、ページ自体はスクロールさせない。見た目は現状と同等に保つ。
4. **モバイル**：既存のタブUI（コマンド／メッセージ／装備）を維持し、戦闘画面が 100dvh に収まること。横はみ出し（horizontal overflow）も出さない。
5. **変更範囲**：見た目・レイアウトのみ（`src/App.tsx`、`src/components/BattleStage2D.tsx` の高さ扱い、必要なら `src/index.css`）。ゲームロジック、シミュレーション、データ、セーブ形式には触らない。最大幅 1760px と既存の配色・カードデザインは維持。
6. **リグレッション禁止**：直前の修正（複数体戦闘で敵HPカードを最大幅 224px に制限、head `98e824c`）を壊さない。
7. テスト全件パス、ビルド成功を確認して push すること。完了報告には、高さ配分の考え方（どの要素が flex で伸縮し、どこが内部スクロールか）を簡潔に含めること。

## 検証（こちらでも実施する）

- Playwright で 1920×1080 / 1440×900 / 1366×768 / 390×844、フロア1と51Fの戦闘画面で `scrollHeight - innerHeight <= 0` を確認する。
- コマンドボタンがスクロールなしでクリックできること、メッセージログが内部スクロールすることを確認する。
