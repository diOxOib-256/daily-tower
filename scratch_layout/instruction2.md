# 実装指示：レイアウト仕上げ（装備レール位置・ゴールド表示・踏破報酬オーバーレイ）（2026-11-19）

対象リポジトリ：`ysgekzk-boop/daily-tower`
前提 head：`e45c605`（スクロールなしレイアウト実装済み）。この上に実装すること。

ユーザーの設計決定に基づく仕上げです。現在のレイアウト（ステージ全幅→コマンド→メッセージ＋装備の下段帯）を、次の形に変えます。

## 1. 装備レールはステージの横だけに置く（PC / lg 以上）

- 画面構成を「1段目：ステージ＋装備レール」「2段目：コンソール（コマンド等）全幅」「3段目：メッセージログ全幅」の3段にする。
- 装備レールは**ステージと同じ高さ**でステージの右に置く（幅は現行の下段装備欄と同じ 380px 目安）。コマンド部分より下には入らない。
- レールの中身は**武器・防具・レリックのみ**（スキルと消耗品の欄はレールから削除する。スキルと消耗品はコマンドカードで見られるため）。モバイルの装備タブ（`equipmentStatusContent`）は従来どおりスキル・消耗品を含む全文のままでよい。
- 武器・防具・レリックだけだとレール内に余白ができすぎるため、**各装備カードのサイズや中身を調整して余白をなるべく少なく**設計すること。例：カードをレールの高さに均等に伸ばす（flex で3等分）、スプライトを大きめに表示、名前・ステータスに加えて説明文もカード内に収める、余白（padding）を広げる。ステージが低い画面（ノートPC等）で収まらない場合はレール内部スクロールにフォールバックしてよいが、原則は1画面に収まる配分にする。
- 現在の装備表示（`equipmentStatusContent`、App.tsx 594行付近）は武器・防具・レリック・スキル・消耗品を含む。レール用に武器・防具・レリックのみの大きなカード版を用意し、モバイル用は既存を維持する形で実装すること（既存の装備行の部品を再利用してよい）。
- 下段帯（メッセージ＋装備の grid）は PC ではメッセージログのみ（全幅）にする。モバイルの3タブUI（コマンド／メッセージ／装備）は現状維持。

## 2. ゴールド入手はメッセージなし＋ヘッダーに「+N」を数秒表示

- 戦闘勝利パネルの「+{totalGoldReward} G を手に入れた」の行（App.tsx 977行付近）を削除する。
- 戦闘ログ等にゴールド入手そのものを知らせる行があれば、同様に削除する（アイテム分解のログなど、アイテムの出来事を伝える行は残してよいが、ゴールド額の告知は落とす）。
- 代わりに、ヘッダーのゴールド表示（💰 {gold} G のピル）のそばに、**ゴールドが増えたときにだけ「+{増加分}」を数秒間（2.5〜3秒目安）表示**する。実装は App で前回のゴールド値を保持し、増加を検出して表示する形でよい。表示中にさらに増えたら増加分を合算して表示時間を延長する。初回マウント時（セーブ読み込み・レルム開始の初期所持金など）には表示しない。ゴールドの消費では何も表示しない。
- ゴールドの増減ロジック自体（報酬額・分解額・イベント等）は変更しない。表示だけの変更。

## 3. 踏破報酬はステージ上のオーバーレイにし、比較欄を削除

- 現在、踏破報酬（`stage === 'floor_reward'`）はコンソール内にカードを並べている。これを**ステージ領域に重ねるオーバーレイ表示**に変える：ステージラッパー（relative）の中に absolute オーバーレイ（半透明の暗幕＋中央にカード横並び、最大3枚）を出し、そこで選択する。選択後の挙動（装備の付け替え、スキル満杯時の `skill_replace_prompt` への遷移など）は現行どおり。`skill_replace_prompt` は従来どおりコンソール表示のままでよい。
- 報酬カード内の「現在の武器：…」「現在の防具：…」「現在のスキル：…」といった**現在の装備との比較欄はすべて削除**する（カードはスプライト・名前・種別・説明のみ）。装備の現物は右レールで確認できる前提の設計。
- `floor_reward` の間、コンソールには短い案内（例：「ステージ上のカードから報酬を選んでください」）だけを出し、高さを取らないこと。
- オーバーレイはモバイルでもステージ上に表示する（ステージが小さい場合はオーバーレイ内部でスクロール可）。

## 4. スクロールなしの維持（必須の受け入れ条件）

- 戦闘中・勝利時・踏破報酬オーバーレイ表示時のすべてで、1920×1080 / 1440×900 / 1366×768 / 390×844 の各ビューポートで `scrollHeight - innerHeight <= 0` かつ `scrollWidth - innerWidth <= 0` を満たすこと（現行の headless Chromium 検証スクリプトと同等の方法で確認すること）。
- ゲームロジック、シミュレーション、データ、セーブ形式は変更しない。変更は表示・レイアウトのみ（主に `src/App.tsx`、必要なら関連コンポーネント）。
- 敵HPカードの最大幅修正（98e824c）など既存の表示仕様を壊さない。
- テスト全件パス、ビルド成功を確認して push すること。完了報告には、レールの高さ配分（カードをどう伸ばして余白を埋めたか）と、各状態（戦闘／勝利／報酬）でのはみ出し実測値を含めること。
