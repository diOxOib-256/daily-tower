# リメイク Block 2 分割実装（全5パート）

Daily Tower のフロア11〜20をリメイク案の内容に置き換える作業を、5パートに分けて実装しています。このファイルがあなたの担当パートの指示です。書かれていることだけを実行してください。

共通ルール：
- 変更は src/extensible/ 配下のみ。**src/core/ は変更禁止**（パート4で明示する2ファイルだけ例外）。
- ゲーム内UIに開発者向けの文言や更新履歴を入れないこと。
- 完了条件：npm test 全件パス、npm run build 成功、その状態で main へ push すること。
- 完了報告に、変更ファイル一覧・テスト／ビルド結果・指示から変えた点（あれば全部）を書くこと。

## パート1/5：敵10種とスプライトの登録

- 下記の通常敵8種・ミニボス2体を src/extensible/enemies/enemyRegistry.ts に登録する。ミニボス2体は既存のミニボスエントリと同じ形式（isBoss: true）で登録する。
- canopy_spider は既存エントリの**同ID再定義**（ステータス・弱点・耐性・フェイズ・スプライト・マトリクス・パレットを下記で置き換え）。
- **ガーゴイルのIDについて（重要）**：案の「苔のガーゴイル (moss_gargoyle)」は、既存の moss_gargoyle（37F以降に登場する別個体）とIDが衝突するため、敵・スプライト・パレットすべて **mossy_gargoyle** というIDで登録すること。表示名「苔のガーゴイル」はそのまま。既存の moss_gargoyle には一切触れないこと。
- 新規スプライト5種（canopy_spider（差し替え）/ hollow_dryad / mossy_gargoyle / deepwood_viper / ancient_wisp_lord）のマトリクスとパレットを spriteRegistry / matrixRegistry に登録する。パレット名はスプライトと同名にする（canopy_spider のパレットは既存エントリの色を案の色で置き換える）。
- deepwood_viper のマトリクスは、このファイルに記載の時点で欠陥行を修正済み（全32行×32要素）。記載どおりに登録すること。
- 流用指定の敵（mist_wolf / spore_goblin / frost_slime / charred_sapling / ironbark_sentinel）は既存の spriteId / palette を使う。ironbark_sentinel の palette ancient_bark が spriteId colossus 用に登録されていない場合は、既存の ancient_bark と同じ色で colossus 用に追加登録する。
- フロアデータ・アイテム・イベントはこのパートでは変更しない。
- コミットメッセージ：`[CF-Pages-Skip] Remake Block 2 (1/5): enemies and sprites`
