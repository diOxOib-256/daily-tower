# リメイク Block 2 分割実装（全5パート）

Daily Tower のフロア11〜20をリメイク案の内容に置き換える作業を、5パートに分けて実装しています。このファイルがあなたの担当パートの指示です。書かれていることだけを実行してください。

共通ルール：
- 変更は src/extensible/ 配下のみ。**src/core/ は変更禁止**（パート4で明示する2ファイルだけ例外）。
- ゲーム内UIに開発者向けの文言や更新履歴を入れないこと。
- 完了条件：npm test 全件パス、npm run build 成功、その状態で main へ push すること。
- 完了報告に、変更ファイル一覧・テスト／ビルド結果・指示から変えた点（あれば全部）を書くこと。

## パート4/5：レリック2種・消耗品2種・新規効果2種と、勝利時回復の配線

### A. 新規効果2種（src/extensible/effects/effectRegistry.ts）
既存エントリと同じ形式で追加する。
- mist_charm：trigger: 'battle_start'。handler は mist_veil_bell と同じ形で、applyStatusToEnemy: { statusId: 'def_debuff', value: 10, duration: 2 } を返す。logMessage は `[レリック:霧の護符] 霧が敵を包み、防御力を10%低下(2T)させた！` とする。**（注意：案の元の効果は atk_debuff だったが、既存の霧隠れの鈴と重複するため def_debuff に変更済み。この指示が正）**
- amber_heart：trigger: 'battle_victory'。handler は ctx を使い、healPlayer: Math.max(1, Math.floor(ctx.playerMaxHp * 0.08)) を返す。logMessage は `[レリック:琥珀の核] 温かな光が傷を癒やした！` とする。

### B. 勝利時回復の配線（**この2ファイルだけは extensible 外の変更を許可する**）
現状、battle_victory 効果の healPlayer はどこにも適用されていない。次の2か所だけを、指定どおりに最小変更する。他のファイル・他の箇所は変更しないこと。
- src/store/useGameStore.ts の proceedAfterCombatVictory：battle_victory 効果のループで res.healPlayer も bonusHeal に累積し、updatedSave.midFloor.playerCurrentHp を Math.min(battleSession.player.maxHp, battleSession.player.currentHp + bonusHeal) にする。
- src/sim/runSimulation.ts の battle_victory 効果のループ（res.grantGold を処理している箇所）：res.healPlayer があれば session.player.currentHp = Math.min(session.player.maxHp, session.player.currentHp + res.healPlayer) を加える（save.midFloor.playerCurrentHp への反映より前の位置）。

### C. レリック2種（RELIC_CATALOG）
- mist_charm（霧の護符）：effectId: 'mist_charm', salvageGold: 18, 説明文: 「冷たい樹海の霧を封じた護符。戦闘開始時、敵全体の防御力をわずかに削ぐ。」

### D. 消耗品2種（CONSUMABLE_CATALOG）
消耗品に salvageGold フィールドはない（付けない）。

- どちらも新規スプライト＋新規パレット、spriteId はアイテムIDと同名。
